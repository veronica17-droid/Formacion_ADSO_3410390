Preguntas frecuentes

¿Por qué el primer error de software de la historia se llamó "bug" (bicho)?

En 1947, la científica Grace Hopper estaba trabajando en la computadora Mark II de Harvard. El sistema falló y, al revisar los relés electromagnéticos, encontraron una polilla real atrapada en los circuitos. La pegaron con cinta en la bitácora del proyecto con la anotación: "Primer caso real de un bicho (bug) siendo encontrado". Desde entonces, resolver fallos se llama debugging.

¿Qué es el "Hoisting" en JavaScript?

Es un comportamiento nativo de JavaScript donde las declaraciones de variables (con var) y funciones se "elevan" lógicamente a la parte superior de su contexto de ejecución antes de que se ejecute el código. Esto permite llamar a una función antes de la línea donde está escrita. (Nota: Las variables declaradas con let y const también se elevan, pero no se inicializan, quedando en una "zona muerta temporal" que lanza un error si intentas usarlas antes).

¿Qué significa que una API sea RESTful?

Significa que sigue las restricciones de la arquitectura REST. Las más importantes son: utilizar los métodos HTTP de forma semántica (GET para leer, POST para crear, PUT/PATCH para actualizar, DELETE para borrar), ser stateless (sin estado, cada petición debe llevar toda la información necesaria) y manejar recursos identificables mediante URIs claras.
